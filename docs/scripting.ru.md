# Написание скриптов

*[English version](scripting.md)*

Скрипт — это файл в каталоге `scripts/` рядом с программой. Он загружается при старте, вычисляется, и
всё, что он определил на верхнем уровне, становится видно остальной программе.

| Расширение | Язык | Чем выполняется |
| --- | --- | --- |
| `.djs` | JavaScript | Rhino, GraalJS или Nashorn — на ваш выбор, по типу файла |
| `.djava` | Java | Компилируется в процессе пакетным компилятором Eclipse |
| `.jar`, `.zip`, `.class` | | Загружается как уже скомпилированный код |

Какой движок выполняет `.djs`, задаётся в *Настройки → Интерпретаторы*. См.
[список движков](architecture.ru.md#парсеры).

## Задание

Любой глобальный объект с членом `main` — это **задание**: оно появляется в выпадающем списке заданий
главного окна, его можно запустить и остановить оттуда. Добавьте ещё `params`, и программа построит
для него форму параметров.

```javascript
Wand = new function() {};
Wand.prototype = {};

Wand.params = {
    name: 'Волшебная палочка',

    // Форма, которая показывается на вкладке параметров.
    config: function(params) {
        return [
            { name: 'type',        label: 'Тип',     type: 'radio', values: ['a', 'b'] },
            { name: 'config_file', label: 'Конфиг',  type: 'file' }
        ];
    },

    defaults: {
        type: 'a',
        config_file: 'private/config.xlsx'
    }
};

Wand.main = function(params) {
    PixelBot.log.info('стартуем с ' + params['type']);

    while (PixelBot.grab_find_click('interface.buttons.close', 1)) {
        PixelBot.sleep(2000);
    }
};
```

В `main` приходят значения параметров, которые ввёл пользователь. `params.config` может быть простым
массивом вместо функции, если форма ни от чего не зависит. Член `active` — булев или функция,
возвращающая булево, — решает, предлагать ли задание вообще.

В `examples/scripts/` лежат исходные задания, ради которых всё писалось: `wand.djs` — самое
маленькое законченное, `hhtools.djs` — самое большое.

## Библиотека

`examples/scripts/pixelbot.djs` — не задание, а библиотека, которой пользуются все остальные скрипты.
Она оборачивает `Helper`, Java-объект, который программа кладёт в скоуп, во что-то более удобное.
Скопируйте её в свой каталог `scripts/` рядом со своими.

Базовый цикл всегда один и тот же: **снять экран, найти элемент, переместиться к нему, кликнуть**.

```javascript
PixelBot.grab();                              // снять весь экран
if (PixelBot.find('interface.buttons.ok')) {  // поискать шаблон
    PixelBot.move_elem();                     // переместиться внутрь найденного
    PixelBot.click(1);
}
```

Почти для каждой комбинации этих шагов есть сокращение — отсюда и длинный список имён:

```javascript
PixelBot.grab_find_click('interface.buttons.ok', 1);
PixelBot.grab_find_click_rect('interface.buttons.ok', 1, x, y, width, height);
```

Варианты с `_rect` ограничивают прямоугольником и снятие экрана, и поиск. Это гораздо быстрее, чем
сканировать весь экран, и именно их стоит использовать внутри цикла.

### Что доступно

| Группа | |
| --- | --- |
| Экран | `grab`, `grab_rect`, `highlight_region`, `screen` |
| Поиск | `find`, `find_rect`, `find_many`, `find_many_rect`, `get_elements` |
| Комбинации | `find_click`, `find_move`, `grab_find`, `grab_find_click` и формы с `_rect` для каждой |
| Мышь | `move`, `move_rel`, `move_click`, `move_rel_click`, `move_elem`, `click`, `mouse.press`, `mouse.release` |
| Клавиатура | `key.click`, `key.press`, `key.release` и константы `key.VK_*` |
| Цвет | `square`, `grab_square` — проверить прямоугольник на попадание в диапазон цвета |
| Капча | `solveCaptcha` — см. [решатель капчи](captcha.ru.md#как-пользоваться) |
| Прочее | `sleep`, `log.{trace,info,warning,error,fatal,success}`, `state`, `statistics`, `sound`, `link`, `browser` |

В `last_find_rect` лежит последнее найденное — от него работают `move_rel` и `move_elem`.
`move_elem` выбирает случайную точку внутри найденного, а не его центр; как и рандомизация таймингов
мыши, это сделано намеренно.

Всё, что библиотека не обернула, доступно через `Helper` напрямую, а Java-классы — через
`Packages.java.…` в Rhino и Nashorn.

## Элементы

Скрипты ссылаются на элементы по имени. Сами шаблоны снимаются в *Настройки → Элементы*: захватить
область экрана, выделить значимую часть, назвать, сохранить. Имена по соглашению разделяются точками,
так что `interface.buttons.close` группируется с соседями в дереве, а `get_elements(category)`
возвращает целую категорию разом.

В этом репозитории шаблонов нет — они были графикой предыдущей цели. Свои вы снимаете сами, под то,
что автоматизируете.

## Выбор движка

**GraalJS** для всего нового: актуальный ECMAScript, живой проект, быстрый.

**Rhino в режиме отладки**, когда нужен пошаговый отладчик — точки останова в поле номеров строк, шаг
внутрь и через, дерево переменных по живому скоупу. Отладку поддерживает только этот бэкенд.

**Rhino в режиме компиляции** — тот же язык, компиляция в байткод, без отладчика.

**Nashorn** — если вы гоняете скрипты, написанные в эпоху Java 8, и что-то в них завязано на
поведение именно этого движка.

Скрипты в `examples/` написаны под Rhino в 2014 году. На других движках они тоже работают, но это
старый JavaScript, и ничего современного они не задействуют.

## Отладка

Откройте скрипт во вкладке редактора, кликните в поле номеров строк, чтобы поставить точку останова,
и запустите задание кнопкой отладки. Когда выполнение встанет, дерево переменных покажет живой скоуп
через ту же модель, которой пользуется остальная программа, — то есть вы видите реальные объекты,
которые определил ваш скрипт, а не их сериализованную копию.

`PixelBot.log.*` пишет во вкладку журнала, туда же попадает всё, что скрипт выводит в стандартный
поток: `BotLogger` перенаправляет оба потока в подсистему логирования.

## Предупреждение

Скрипты выполняются с полным доступом к хосту: в этом весь смысл Java-бэкенда и `Packages.java.…`.
Запускайте только те скрипты, которые написали сами или прочитали.
